# P02｜第二位受访者研究提炼 v0.1

> 来源：方案B低经验情境访谈 + 引导式过程重建  
> 样本类型：邻近目标用户  
> 研究性质：情境回答为主，不等同于完整真实制作行为  
> 当前证据标签：以 `SCENARIO` 为主，部分回答为 `PROMPTED`  
> 注意：以下结论只适用于本次样本，不能直接推广到全部设计学生或xTool用户。

## 1. 样本有效性

### 可以支持

- 初级设计用户如何理解说明书任务；
- 如何寻找竞品、产品信息和设计参考；
- 如何决定说明书形式、尺寸、材料、颜色和版式；
- AI在内容表达、灵感和视觉建议中的作用；
- Figma、Illustrator、KeyShot和工厂之间的预期工具链；
- 用户如何理解交付前检查与人工确认；
- 哪些产品事实不能由AI自行生成。

### 不能直接支持

- xTool Studio具体操作和功能边界；
- SVG Checker规则是否高频；
- 激光切割工作流；
- 实际工厂一定接受其设想的文件包；
- 其设想流程已经真实走通；
- MakerFlow能够减少返工。

## 2. 对任务的初始理解

受访者最初将任务理解为：

- 说明书；
- 包装；
- 商品详情页；
- 产品展示。

这说明其对交付物范围的理解较宽，尚未立即收敛到“包装内高度调节说明卡”。

### 初步判断

> 对低经验用户来说，模糊任务可能首先导致交付物范围不清，而不仅是尺寸或材料缺失。

严重度：S2  
研究优先级：P1（当前单一样本）

## 3. 受访者形成的预期工作流

```text
理解任务
→ 收集产品信息
→ 查看购物平台、设计网站和同类说明书
→ 判断说明书内容、形式、尺寸、材料和包装关系
→ 在Figma整理信息和低保真方案
→ 使用AI进行表达、语气、风格和图案发散
→ 在Illustrator进行设计与排版
→ 使用KeyShot制作配合展示效果
→ 检查内容、配色、字体、格式和尺寸
→ 输出源文件与PDF
→ 交付工厂
→ 根据反馈返回设计工具修改
```

> 该流程是受访者对情境任务的设想，不是完整真实操作记录。

## 4. P0研究发现

### F01｜信息收集是任务起点，也是最希望获得的辅助

受访者反复提到：

- 先收集产品相关信息；
- 查看购物网站、设计网站和现实同类产品；
- 了解竞品说明书的排版、尺寸、材料和展现形式；
- 最希望AI或系统帮助“收集信息”。

初步判断：

> 在进入Brief或设计前，低经验用户首先需要建立可信的信息基础，而不是立即生成视觉结果。

对MakerFlow的影响：

- Creative Brief不能只要求用户手动填写；
- 可以支持从用户提供的产品资料和参考中提取候选字段；
- 仍需用户确认产品事实，不能由AI自行补写。

严重度：S2  
研究优先级：P1

### F02｜用户会先参考竞品，再结合自身产品筛选

受访者不会直接照搬竞品，而是计划根据产品说明、材料相似度、包装关系、品牌风格和实际打样判断哪些内容适合自己的产品。

初步判断：

> 竞品参考主要用于建立候选方案，最终仍需结合产品事实和实际包装条件确认。

对MakerFlow的影响：

- Constraint Recommendations应输出候选方案、依据和限制；
- 不能把竞品结论直接写成产品事实。

严重度：S1  
研究优先级：P1

### F03｜形式、尺寸和材料不是一次确定，而是逐步确认

受访者认为：

- 形式取决于信息量以及与包装、产品的配合；
- 尺寸参考竞品，也需要实际打样和工厂验证；
- 包装空间未知时可以先做“通用方案”和“特定方案”；
- 材料参考竞品和整体设计风格；
- 大致尺寸可暂时使用，但最终信息和尺寸必须确认。

初步判断：

> 用户需要的不是一个自动确定的答案，而是“临时假设—候选方案—实际确认”的决策过程。

对MakerFlow的影响：

- Brief中应区分已确认、临时假设和待确认；
- 尺寸、材料、形式建议应显示依据、权衡和确认状态；
- 不能把推荐值直接标记为生产事实。

严重度：S2  
研究优先级：P1

### F04｜AI被定位为表达、灵感和发散工具

受访者计划将已确认内容交给AI，用于调整排版、语气、表达规范、风格和图案发散。同时明确：

- AI结果只作为灵感；
- 目标用户、使用场景、产品真实参数和操作步骤不能由AI自行编写；
- AI建议需要人确认；
- 是否接受AI建议取决于经验、设计思维和用户反馈。

初步判断：

> 用户接受AI作为建议层，但不愿把事实和最终决策完全交给AI。

对MakerFlow的影响：

- Model负责候选建议；
- Human负责产品事实和最终确认；
- 建议应显示依据、优点、限制和需要确认的部分。

研究优先级：P1

### F05｜多工具流程已形成，但信息连续性认知不完整

受访者预计使用：

```text
Figma
→ 竞品/资料网站
→ AI
→ Illustrator
→ KeyShot
→ 工厂
```

其认为工具切换“没有信息遗漏”，但同时又表示：

- 具体信息内容需要重新输入或重新制作；
- 信息和排版需要在工具间转移；
- 文件在信息转移和交付工厂时需要检查。

初步判断：

> 用户未必会主动把重复录入理解为“信息损失”，但跨工具确实存在重新输入和检查成本。

对MakerFlow的影响：

- 后续访谈不要只问“有没有信息丢失”；
- 应改问“哪些内容需要重新复制、输入、导出或确认”。

严重度：S1—S2  
研究优先级：P1

### F06｜用户认可交付前检查，但制作软件内检查认知模糊

受访者认为交付前需要检查：

- 信息准确性；
- 配色；
- 字体；
- 格式；
- 精确尺寸；
- 文字、图片、路径和文件格式。

同时回答：

- 文件进入制作软件后“无”额外检查；
- 但文件能够导入不代表可以安全加工；
- 仍需查看导入效果和软件设置；
- 尺寸不符时需要检查源文件和导入设置。

这组回答存在不一致。

初步判断：

> 低经验用户知道“导入成功不等于最终正确”，但未形成清晰的“导入前问题—制作软件内问题—加工前确认”分层。

对MakerFlow的影响：

- Checker应明确问题应在哪里解决；
- Studio Setup Checklist需要使用通俗语言；
- 不应假设用户天然理解制作软件内的检查内容。

严重度：S2  
研究优先级：P1

### F07｜所有关键决策均要求人工确认

受访者表示形式、尺寸、材料、颜色、版式、制作路径和格式建议都需要人确认。特别不能完全交给AI的内容包括：

- 产品真实信息；
- 目标用户；
- 使用场景；
- 操作步骤；
- 设计与交付的最终决定。

初步判断：

> Ask-vs-Act需要非常保守，尤其是涉及产品事实、尺寸和最终制作文件时。

研究优先级：P1

## 5. 对MakerFlow假设的影响

| MakerFlow假设 | 当前结果 | 证据说明 |
|---|---|---|
| 用户需要可编辑Creative Brief | 部分支持 | 用户主动拆解产品信息、内容、形式、尺寸和包装关系 |
| 系统可辅助信息收集和字段提取 | 支持 | 信息收集是第一步，也是最希望获得的辅助 |
| 用户需要Constraint Recommendations | 支持 | 用户需要形式、尺寸、材料、颜色和制作路径候选 |
| 建议必须显示依据和权衡 | 支持 | 受访者要求材料、印刷和表达建议有依据、优点和限制 |
| AI不能生成产品事实 | 支持 | 目标用户、参数和操作步骤不能由AI自行编写 |
| 用户需要Pre-import Checker | 部分支持 | 认可交付前检查，但未验证SVG具体规则 |
| 用户需要Studio Setup Checklist | 部分支持 | 对制作软件内检查认知模糊且前后不一致 |
| 用户需要决策记录 | 无法确认 | 未直接测试版本、确认和决策日志的价值 |
| MakerFlow能减少返工 | 无法确认 | 只有情境回答，尚无使用测试 |

## 6. 当前不能确认

- 用户是否愿意真正维护一份Creative Brief；
- 自动提取参考资料是否会带来错误或版权风险；
- Figma与Illustrator之间真实发生了哪些格式损失；
- 工厂具体需要什么文件和说明；
- PDF与SVG的用途认知；
- 哪些SVG规则对该用户真正重要；
- 实际打样是否会改变其尺寸和材料决定；
- Studio内哪些事项应由软件处理。

## 7. 样本最有价值的结论

> P02并没有表现出“我要一个全自动AI设计工具”，而是希望先获得可信信息，再得到带依据的设计与制作建议，并由人确认关键决策。

这支持MakerFlow继续保留：

1. 信息与约束提取；
2. Editable Creative Brief；
3. Constraint Recommendations；
4. Pre-import检查；
5. Studio内Next Step提示；
6. Human Confirmation。

但当前证据仍不足以证明：

- SVG Checker是最高优先级；
- 用户一定需要完整决策日志；
- xTool Studio存在具体缺陷。

## 8. 样本结论

P02是一份有效的低经验情境样本。

与P01相比：

- P01更能证明真实跨工具报错和制作失败；
- P02更能说明用户如何从信息收集、竞品参考和设计建议进入方案；
- 两者共同支持“约束逐步形成”和“人工确认不可缺少”；
- 目前仍需要第三个样本补充交付、文件检查或制作方视角。
