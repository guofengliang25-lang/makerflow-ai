# MakerFlow 一页 Brief

> 阶段：V3-W1-D04｜产品定义  
> 项目性质：个人作品集 Demo，不是企业正式产品  
> 完成状态：协作填写中

## 1. 项目名称

MakerFlow | 从模糊创意到可编辑、可校验、可制作文件的创作Agent

## 2. 一句话定位

MakerFlow AI是一款面向缺少专业矢量设计和机器工艺经验的创作者的AI创作助手，帮助用户将一句*模糊想法*，逐步转化为*结构化设计Brief*、*可编辑设计规格*、*经过规则检查的SVG文件和制作交接信息*。

## 3. 目标用户

- 核心用户：具备基础设计意识，但缺少完整印刷、矢量文件和机器工艺经验的设计学生或初级 Maker。
- 典型场景：用户已有一个需要制作成真实物品的模糊想法，但不确定尺寸、材料、内容层级、文件格式和制作交接要求。
- 用户当前使用的替代方案：用户在 ChatGPT、图片生成工具、Figma、Illustrator、Inkscape、搜索引擎和制作软件之间切换，依靠人工整理需求、排版、导出和检查文件。

## 4. 核心问题

- 用户想完成什么：把一个模糊的小物或包装物料创意，变成能够继续编辑、打印或进入制作软件的文件包。
- 当前最困难的环节：
1. 不知道创意阶段还缺少哪些关键信息；
2. 不理解用途、尺寸、材料、内容与制作方式之间的关系；
3. 不清楚什么时候应继续设计，什么时候必须先确认；
4. 不知道导出的 SVG 是否存在尺寸、文字、位图或路径问题；
5. 文件进入制作软件后才发现错误。
- 困难造成的后果：反复修改、跨工具搬运信息、文件交接不清晰，以及在制作前产生额外返工。
- 为什么值得解决：AI 的价值不应只停留在“生成一个视觉结果”，还应帮助用户补齐约束、保留可编辑中间结果并在进入制作阶段前发现基础问题。

## 5. 产品价值

- 对用户的直接价值：减少从模糊想法到可执行设计需求之间的信息缺口，形成可编辑、可检查、可交接的过程。
- 相比现有方式的差异：
1. 在生成前主动识别缺失约束；
2. 不直接跳到最终图片，而是先输出可编辑 Creative Brief；
3. 明确区分模型判断、规则检查、工具调用和人工确认；
4. 在进入制作软件前完成基础 SVG 检查；
5. 同时交付印刷文件、刀线文件和检查报告。
- 本 Demo 希望证明的产品判断：面向制作任务的 AI 助手，应优先帮助用户澄清目标和工艺约束，并保留人工确认点，而不是只追求一次性生成结果

## 6. 核心使用场景

| 场景 | 触发条件 | 用户输入 | 预期结果 |
|---|---|---|---|
| 需求澄清 | 用户只提供模糊目标，缺少尺寸、形式、内容或制作方式 | 帮我做一份 MomoRay 枕头高度调节说明书 | 系统识别缺失字段，提出少量关键问题并解释提问原因 |
| Creative Brief | 用户已回答必要问题 | 用途、目标用户、已有文案、尺寸、折页形式、品牌素材 | 输出结构化且可编辑的 Brief，明确已确认信息、默认假设和待确认项 |
| 设计规格与文件准备 | Brief 已由用户确认 | 已确认 Brief、品牌资产和内容 | 输出内容层级、页面结构、版式约束，以及印刷 PDF 和 SVG 刀线的准备要求 |
| SVG 检查 | 用户上传或系统生成 SVG 刀线/矢量文件 | SVG 文件 | 输出结构化检查报告，标记尺寸、单位、文字、位图、路径和图层问题 |
| 制作交接 | 文件通过基础检查 | 印刷 PDF、SVG、检查报告、材料和尺寸信息 | 形成制作交接包，并提示哪些参数仍需人工或设备端确认 |

## 7. 核心流程

1. 用户输入模糊想法
2. 系统提取已有信息并识别缺失约束；
3. Ask-vs-Act 模块判断应追问、采用显式假设继续，还是要求用户确认；
4. 形成结构化Creative Brief
5. 用户编辑并确认Brief，生成设计规格与SVG
6. 调用SVG Checker，返回错误、风险和修改建议
7. 用户确认，导出SVG + 制作交接信息
8. 导入xTool Studio验证

## 8. Ask-vs-Act 边界

| 情况 | 行为 | 原因 |
|---|---|---|
| 缺少会显著改变结果的关键信息 | Ask | 避免基于错误假设继续 |
| 信息足以生成安全、可逆的初稿 | Act | 减少不必要的追问 |
| 涉及不可逆、高风险或对外发布 | Ask | 需要用户明确确认 |
| 仅缺少不影响主方向的细节 | Act，并显式标注假设 | 保持任务连续 |

### MakerFlow 场景中的具体规则

**必须追问：**

- 成品尺寸或展开尺寸未知；
- 折页、单页、卡片等形式未确定；
- 必须出现的文案、警示语或产品事实不完整；
- 使用材料、印刷方式或是否需要机器裁切未知；
- 品牌 Logo、字体和产品结构信息缺失；
- 用户要求直接发送印刷、加工或对外发布。

**可以先行动，但必须标注假设：**

- 图标风格、装饰元素、辅助色和初稿栅格未确定；
- 用户只需要内部讨论版或低保真草稿；
- 缺失信息不会改变内容结构和制作安全；
- 可随时撤销或修改的版式建议。

**必须由人工确认：**

- 最终文案和产品功能描述；
- 最终尺寸和折叠方式；
- 印刷文件和刀线文件；
- 材料与设备兼容性；
- 实际切割、加工和对外发布。

## 9. MVP 范围

### 计划包含

| 模块             | MVP内容 |
| -------------- | --------------------- |
| 意图澄清           | 识别用途、尺寸、材料、文字、风格等缺失信息 |
| Ask-vs-Act     | 判断应该追问还是可以继续          |
| Creative Brief | 输出结构化、可编辑的设计需求        |
| Design Spec    | 输出尺寸、版式、内容和制作约束       |
| SVG Checker    | 检查已定义的确定性规则           |
| Export Pack    | 输出SVG、检查报告和制作交接信息     |

### 明确不包含

- 企业级生产能力；
- 正式商业承诺；
- 尚未验证的真实模型集成；
- 自动替代设计师完成全部视觉决策；
- 自动确定激光功率、速度等设备安全参数；
- 直接控制激光设备；
- 适配所有印刷厂、材料和机器；
- 保证文件一定能够安全加工；
- 正式上线、真实用户规模或业务增长结果；
- 将首个案例直接用于 MomoRay 实际销售包装。

## 10. 内部 Tool

SVG Checker 是 MakerFlow 内部 Tool，用于检查已定义的 SVG 规则。

- 计划检查的规则：

1. 文件是否能够被正常解析；
2. 是否包含`viewBox`；
3. 是否声明宽度、高度和单位；
4. SVG 画布尺寸是否与 Brief 中的成品或展开尺寸一致；
5. 是否存在仍未转路径的文字对象；
6. 是否包含嵌入位图；
7. 是否存在空路径、重复 ID 或异常元素；
8. 刀线图层是否存在；
9. 刀线路径是否存在未闭合情况；
10. 路径数量是否超过项目预设的复杂度提示阈值。

- 输入：
- SVG 文件；
- Creative Brief 中的目标尺寸；
- 文件用途：印刷图形 / 刀线 / 组合文件；
- 项目预设检查规则。

- 输出：

- `checker_report.json`；
- 通过、警告和阻塞问题列表；
- 问题位置；
- 修改建议；
- 已检查规则和未覆盖范围。

- 不负责的事项：

- 不判断视觉设计是否好看；
- 不验证文案和产品事实是否正确；
- 不自动确定设备参数；
- 不保证文件适配所有机器；
- 不保证实际加工安全；
- 不替代 xTool Studio 或设备端最终确认；
- 不属于工业级生产校验系统。

## 12. 成功标准

| 指标 | 定义 | 目标 | 验证方法 |
|---|---|---|---|
| Brief 信息完整度 | 是否包含用途、用户、形式、尺寸、材料、内容和输出要求 | 10 个测试案例中至少 8 个生成完整必填字段 | 使用固定案例和字段检查表 |
| Ask-vs-Act 一致性 | 系统行为是否符合已定义政策 | 10 个边界案例中至少 8 个判断符合预期 | 人工标注标准答案后进行对照 |
| SVG Checker 规则准确性 | 工具能否识别预设的有效和错误文件 | 首批 8 个测试 SVG 的预期与实际结果全部一致 | 单元测试与测试报告 |
| 软件导入有效性 | 文件能否在 xTool Studio 中打开且尺寸一致 | 至少 3 个样例成功导入，尺寸偏差原因可解释 | 导入截图和尺寸对照记录 |
| 制作交接完整度 | 是否同时包含印刷文件、刀线、检查报告和确认项 | 首个案例形成完整交接包 | 文件清单人工复核 |
| 证据可追溯性 | 是否保存输入、输出、版本、环境和实际状态 | 每个关键测试均有证据编号 | 证据登记表 |
| 真实模型验证 | 真实 API 是否完成最小闭环 | API 恢复后完成，不纳入当前完成状态 | Responses API 日志与 Eval |

## 13. 关键假设与风险

| 假设或风险 | 为什么重要 | 验证方法 | 当前状态 |
|---|---|---|---|
| 初级 Maker 确实难以从模糊想法进入制作文件 | 决定产品问题是否真实 | 5 名目标用户访谈或任务观察 | 待验证 |
| 主动澄清比直接生成更有价值 | 决定 Agent 的核心交互方式 | 对比任务测试和用户反馈 | 待验证 |
| 包装内折页说明卡能同时证明内容、印刷和文件交接能力 | 决定自证物是否足够有代表性 | 完成首个案例后复盘 | 已选择，待验证 |
| 纸张说明卡与 SVG/xTool 流程可能不完全重合 | 避免为了展示机器流程而强行使用工具 | 将印刷 PDF 与 SVG 刀线分开验证 | 已识别并修正 |
| 无法接触激光设备 | 影响真实加工证据 | 先完成文件层和软件层验证，继续寻找学校或外部设备 | 未确认 |
| API Billing 持续阻塞 | 影响真实模型集成和效果评测 | Mock-first 架构，API 恢复后补测 | 当前阻塞 |
| 项目范围过大 | 可能导致无法完成可演示 Demo | 固定一个用户、一个自证物和一条主流程 | 已控制 |

## 14. 一页结论

### 已确认

- 核心用户：设计学生和初级 Maker；
- 首个验证案例：MomoRay 模块化枕头包装内折页说明卡；
- 材料方向：纸张或卡纸；
- 输出包：印刷 PDF、SVG 刀线/矢量文件和检查报告；
- xTool Studio 可以安装，用于软件层导入验证；
- SVG Checker 并入 MakerFlow，作为内部确定性 Tool；
- 项目为个人作品集 Demo；
- 真实 API 当前未完成。

### 仍需确认

- 说明卡实际展开尺寸和折叠后成品尺寸；
- 页数或折页结构；
- 纸张类型、克重与印刷方式；
- 是否需要异形刀线；
- MomoRay 最终批准文案和品牌素材；
- 是否能接触激光切割或刀片切割设备；
- 具体设备型号；
- 目标用户问题能否通过真实访谈验证。

### 进入下一阶段的条件

1. 填写实际尺寸和折页结构；
2. 整理 MomoRay 可使用的产品事实与品牌素材；
3. 完成 5 个创作到制作工作流研究；
4. 完成目标用户访谈提纲；
5. 建立首批 Ask-vs-Act 案例；
6. 建立首批 SVG 正常与错误测试文件；
7. API 阻塞不影响进入产品研究阶段。
