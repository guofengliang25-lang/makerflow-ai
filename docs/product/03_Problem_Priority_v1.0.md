# MakerFlow Problem Priority v1.0

> 阶段：W2产品研究结论  
> 输入：P01、P02、P03与Evidence Matrix v1.0  
> 目的：区分问题严重度、证据强度与MVP优先级，避免用功能偏好替代研究证据

## 1. 三条独立判断轴

### 严重度S0—S3

| 等级 | 定义 |
|---|---|
| S0 | 当前未观察到明显任务影响，或只是背景信息 |
| S1 | 轻微摩擦，可继续完成，不产生明显返工 |
| S2 | 明显增加理解、整理、等待或返工成本 |
| S3 | 阻止任务继续、导致高成本重做，或涉及不可逆与安全风险 |

### 证据强度

| 等级 | 定义 |
|---|---|
| 强 | 至少两份真实行为证据方向一致 |
| 中 | 一份真实行为证据，加情境或间接证据 |
| 弱 | 单一样本、情境回答或研究者推断为主 |
| 无 | 当前没有相关研究数据 |

### MVP优先级P0—P2

| 等级 | 定义 |
|---|---|
| P0 | 单一MVP主任务必须处理，否则无法验证核心价值 |
| P1 | 重要辅助或需要下一轮验证，但不阻塞主流程 |
| P2 | 扩展能力、低证据能力或当前明确不做 |

严重度高不自动等于P0；例如设备安全问题严重度为S3，但应由实际软件、设备和人工流程处理，不属于SVG File Check自动解决范围。

## 3. P0问题详解

### PR-01／PR-02｜约束不完整且状态混杂

- 证据：三人均出现不完整输入；P02和P03明确支持临时值与最终确认的区别；
- MVP响应：Editable Creative Brief显示`confirmed`、`assumed`、`missing`、`needs_confirmation`；
- 真实性边界：尚未证明用户愿意主动填写复杂Brief，因此必须用轻量原型验证。

### PR-04／PR-05｜问题后置暴露且解决位置不清

- 证据：P01、P03均有真实上游问题进入下游后暴露的经历；P02对阶段边界认知不完整；
- MVP响应：MakerFlow Preflight将问题分配给SVG File Check、Brief Consistency Check或Studio Readiness Checklist；
- 真实性边界：P01/P03是3D模型工作流，只支持分阶段架构，不能证明SVG规则频率。

### PR-06｜导入状态被过度解释

- 证据：P01/P03均表明进入切片后仍可能失败；P02情境回答也认为可导入不等于安全加工；
- MVP响应：所有通过状态必须说明“通过当前规则”，并列出仍需人工处理的事项；
- 边界：MakerFlow Preflight不验证材料参数，也不提供生产就绪或安全认证。

### PR-07｜AI与人工责任边界

- 证据：三人均保留事实、尺寸、方案或最终制作的人工确认；
- MVP响应：模型提供候选和解释，规则决定门槛，工具执行确定检查，人完成高影响确认；
- 边界：机器功率、速度、次数和安全参数不由MakerFlow自动决定。

## 4. P1问题

### PR-03｜跨工具上下文

MVP只保存：已确认Brief、候选建议确认、Preflight结果、修复版本和未完成清单。不尝试同步全部设计工具数据。

### PR-08｜Constraint Recommendations

保留候选建议、依据、收益、取舍、置信度和确认要求，但不作为MakerFlow核心差异。

### PR-10／PR-11｜SVG与xTool专项验证

- 需要收集真实SVG文件及其导入结果；
- 需要实际安装并记录xTool Studio版本、输入文件、尺寸和表现 `[待实际验证]`；
- 未验证前不得根据3D模型访谈确定SVG规则频率或Studio缺陷。

## 5. 本轮范围调整

至少一项证据导致了范围变化：

1. 原先单一文件检查名称不再作为包办式总称，统一为 **MakerFlow Preflight**；
2. Preflight拆成 **SVG File Check**、**Brief Consistency Check**、**Studio Readiness Checklist**；
3. 制作设置、材料参数、Preview/Framing和设备安全明确留在Studio、设备与人工侧；
4. Constraint Recommendations从潜在差异降为P1辅助层；
5. 3D模型Checker不进入MVP；
6. 完整决策日志降为P2，只保留关键确认记录。

以上为`[研究者推断]`的产品决策。
