# MakerFlow Evidence Matrix v1.0

> 阶段：W2 产品研究结论整理  
> 样本：P01、P02、P03  
> 证据结构：P01、P03以真实经历为主；P02以`SCENARIO`情境回答为主  
> 真实性边界：本矩阵不证明MakerFlow已经有效，也不证明SVG问题或xTool Studio问题的市场频率

## 1. 证据口径

### 支持状态

- **支持**：样本提供了与判断直接相关的行为或明确回答；
- **部分支持**：方向相关，但样本、任务类型或证据形式存在限制；
- **反对**：样本提供与判断相反的行为或回答；
- **无法判断**：未问到、回答不足，或证据不能安全外推。

### 证据强度

- **强**：至少两份真实行为证据方向一致；
- **中**：一份真实行为证据，加一份情境或间接证据；
- **弱**：主要来自单一样本、情境回答或研究者推断；
- **无**：没有相关研究数据。

证据强度仅针对当前三人样本，不代表统计意义或目标市场频率。

## 3. 当前被证据支持的范围调整

1. 将原先单一文件检查总称升级为总能力 **MakerFlow Preflight**；
2. 将其拆为 **SVG File Check**、**Brief Consistency Check** 和 **Studio Readiness Checklist**；
3. 将文件层问题与制作设置、材料、设备及加工安全分开；
4. 保留Constraint Recommendations，但降为P1辅助层；
5. 保留人工确认门，不允许未确认的高影响事项自动进入下一阶段；
6. 不把3D模型检查纳入当前MVP。

以上为`[研究者推断]`形成的产品范围选择，不是受访者直接提出的功能清单。

## 4. 仍未验证的产品假设

- 用户是否愿意使用和维护Editable Creative Brief；
- 哪种约束状态表达最容易理解；
- 具体哪些SVG规则最常见、最严重；
- Brief Consistency Check能否正确帮助用户发现尺寸或用途不一致；
- 用户能否理解SVG File Check与Studio Readiness Checklist的边界；
- xTool Studio对SVG/PDF的真实导入、尺寸解释和对象识别行为 `[待实际验证]`；
- Studio内实际需要哪些设置、Preview/Framing和加工前确认 `[待实际验证]`；
- Constraint Recommendations是否值得使用、会不会增加决策负担；
- 轻量决策记录是否有价值；
- MakerFlow是否能够减少返工、时间或错误；
- 用户是否愿意持续使用或付费。
