# MakerFlow JTBD v1.0

> 阶段：W2产品研究结论  
> 证据来源：P01、P02、P03与`05_Evidence_Matrix_v1.0.md`  
> 真实性边界：JTBD是跨样本综合；研究者组合和措辞均标记为`[研究者推断]`

## 1. 目标用户

有基础设计能力，但缺少完整制作交接经验的设计学生或初级Maker。

当前三人样本均为邻近用户：P01为设计学生与3D打印项目参与者，P02为低经验情境用户，P03为3D打印制作侧从业者。三人均不是xTool Studio专项用户。

## 2. 主JTBD

> `[研究者推断]` 当我拿到一个信息不完整、最终需要进入设计与制作流程的任务时，我希望逐步确认关键约束，并知道文件与制作问题应在哪个阶段、由谁处理，以便形成可继续编辑和交接的文件，同时保留对高影响决定和最终加工的控制权。

证据：J01、J02、J03、J05、J06、J09。

## 3. 功能任务

| 功能任务 | P01证据 | P02证据 | P03证据 | 当前状态 |
|---|---|---|---|---|

## 4. 情绪任务

以下均为`[研究者推断]`，当前访谈没有直接量化情绪强度：

- 希望知道下一步应做什么，降低面对不完整任务时的不确定感；
- 希望在交付或制作前看见仍未解决的风险；
- 希望AI提供帮助，但不夺走最终判断权；
- 希望能够解释为什么当前可以继续或必须停止；
- 希望失败后知道返回哪个工具、从哪一步恢复。

证据基础：P01-F02/F04/F06、P02-F03/F06/F07（`SCENARIO`）、P03-F02/F03。

## 5. 触发条件

- 收到口头、聊天、课程要求或零散资料形成的不完整任务；
- 结果需要从设计工具进入制作软件、工厂或真实设备；
- 用途、形式、尺寸、材料或内容尚未完全确认；
- 需要在多个工具和角色之间转移信息；
- 文件能否进入下一阶段存在不确定性。

证据：J01、J03、J04。

## 6. 期望结果

- 形成一份可编辑、可确认的任务约束基线；
- 清楚区分已确认、暂定、缺失和需要确认的信息；
- 获得有依据、有取舍、可拒绝的候选建议；
- 在导入前识别当前规则能够确定的文件问题；
- 知道哪些事项需要在Studio或加工前人工处理；
- 获得可继续编辑和交接的SVG/PDF及人类可读记录；
- 失败后能够返回正确阶段修改并复检。

这些是期望结果，不代表MakerFlow已经实现或验证这些结果。

## 7. 失败后果

| 失败后果 | 证据 | 边界 |
|---|---|---|
| 上游问题在下游才暴露，必须返回修改 | P01-F02/F03、P03-F02 | 真实行为来自3D工作流，不能直接等同于SVG频率 |
| 文件、格式或几何错误导致任务中断 | P01-F02/F04、P03-F02/F03 | 不代表MakerFlow Preflight能覆盖全部问题 |
| 制作设置或设备问题造成试样失败 | P01-F04、P03-F03 | 属于制作环境和设备侧，不属于SVG File Check |
| 产品事实或关键尺寸未经确认 | P02-F04/F07（`SCENARIO`）、P01-F06 | 后果强度尚未通过真实说明卡制作验证 |
| 多工具转移带来重复整理和版本负担 | P01-F02、P02-F05（`SCENARIO`）、P03工作流 | P03的信息损失程度仍不能确认 |

## 8. 与MakerFlow产品范围的关系

`[研究者推断]` JTBD支持保留：

- 缺失信息识别与Ask-vs-Act；
- Editable Creative Brief；
- 人工确认门；
- MakerFlow Preflight；
- 问题阶段路由与修复/复检；
- Constraint Recommendations作为辅助能力。

JTBD不支持把MakerFlow扩展为完整设计工具、3D模型修复器、xTool Studio替代品或自动设备控制系统。

## 9. 尚未验证

- 用户是否愿意实际维护Brief；
- 哪种约束状态表达最容易理解；
- 是否真的减少时间、返工或错误；
- 用户对MakerFlow Preflight三个子模块的理解；
- SVG具体规则的频率和优先级；
- xTool Studio专项用户是否具有相同JTBD；
- 长期使用和付费意愿。
