# MakerFlow Constraint Recommendations

> 阶段：W2 产品定义  
> 能力定位：Creative Brief 确认后的辅助建议层，不是 MakerFlow 核心差异  
> 当前状态：产品契约，尚未实现或运行

## 1. 目的

Constraint Recommendations 根据用户已经确认的 Creative Brief 约束，提供可以比较、编辑、接受或拒绝的候选建议。它帮助用户理解约束之间的关系，但不把建议伪装成事实，也不替用户完成不可逆或高风险决定。

## 2. 进入条件

只有满足以下条件后才能生成建议：

1. Creative Brief 已由用户确认；
2. 建议引用的约束可以追溯到已确认字段；
3. 仍未确认的内容保持为待确认项，不得作为确定依据；
4. 如果缺失信息会改变文件结构、制作路径或安全边界，应返回 Ask-vs-Act，而不是生成确定建议。

## 3. 建议类别

每组建议可以覆盖以下七类：

1. `form`：形式，例如单页、折页或卡片；
2. `dimensions`：尺寸及尺寸之间的关系；
3. `material`：材料方向；
4. `color`：颜色数量、对比和使用原则；
5. `layout_readability`：版式、字号、信息层级和可读性；
6. `production_path`：设计、导出、检查和软件交接路径；
7. `output_format`：SVG、PDF 或其他已确认用途所需格式。

材料、制作路径和 xTool 相关建议如果没有实际软件、材料或设备证据，必须标记 `[待实际验证]`。

## 4. 单条建议字段

| 字段 | 含义 | 规则 |
|---|---|---|
| `recommendation` | 候选做法 | 使用可行动语句，不写成系统已自动决定 |
| `based_on` | 建议引用的已确认约束 | 至少一项；不得引用未确认假设作为事实 |
| `benefit` | 采用建议的预期收益 | 描述与当前任务直接相关的收益 |
| `tradeoff` | 采用建议的代价或限制 | 不得省略成本、限制或替代方案 |
| `confidence` | 依据充分程度 | `low`、`medium`、`high`；不是加工成功概率 |
| `requires_user_confirmation` | 是否必须由用户确认 | 涉及尺寸、材料、输出用途或制作路径时通常为 `true` |

## 5. 交互与状态规则

- 用户可以接受、拒绝或编辑每条建议；
- 建议在用户确认前不得写回 Creative Brief 的已确认字段；
- 接受或拒绝的结果进入用户项目决策记录；
- 相互冲突的建议必须并列呈现差异和取舍；
- 没有充分依据时使用 `low`，并说明需要补充的验证；
- 用户拒绝建议不影响原始 Creative Brief 的有效性；
- Constraint Recommendations 不直接生成“Verified”状态。

## 6. 责任边界

### 可以做

- 基于已确认用途提出形式、尺寸和版式候选；
- 解释材料方向对版式、输出和制作路径的影响；
- 建议为不同用途准备 SVG 或 PDF；
- 提示哪些建议需要在设计工具、xTool Studio 或加工前确认 `[待实际验证]`。

### 不可以做

- 自动决定机器功率、速度、次数和安全参数；
- 保证某种材料与设备兼容；
- 将通用材料信息包装成实际设备验证结果；
- 替代 Preview/Framing、材料测试、操作人员确认或设备安全检查；
- MakerFlow 的核心差异不包含材料选择或参数建议；
- Recommendation JSON 仅作用户项目记录；当前没有已验证的 xTool Studio 自动互通能力。

## 7. 与主流程的关系

`Editable Creative Brief → Constraint Recommendations → 用户确认 → 候选设计文件`

Brief 是用户确认的需求基线；Recommendations 是可选辅助；确认记录是用户项目记录；候选设计文件才进入后续 Pre-import SVG Checker。

## 8. 成功标准

- 每条建议完整包含六个必填字段；
- 每条建议能追溯到至少一个已确认约束；
- 收益与取舍同时存在；
- 未确认建议不会被写成事实；
- 不包含机器功率、速度、次数或安全参数决定；
- 所有未验证的 xTool 能力均标记 `[待实际验证]`。
