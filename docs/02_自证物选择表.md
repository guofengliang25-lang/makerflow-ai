# MakerFlow 自证物选择表 v1.0

> 项目性质：个人作品集 Demo  
> 核心自证物：MomoRay 模块化枕头包装内折页说明卡  
> 原则：自证物证明真实完成的工作和判断，不把计划、Mock 或未执行验证写成真实成果。

## 1. 选择标准

每个候选自证物需要回答：

1. 它证明什么产品能力或判断？
2. 证据能否复现和检查？
3. 招聘方或面试官能否快速理解？
4. 它是否直接服务于 MakerFlow 的核心价值？
5. 当前制作成本是否合理？
6. 它能否区分真实过程、Mock、本地 Tool 和真实模型证据？
7. 它是否与目标岗位要求形成直接对应？

| 优先级 | 自证物 | 选择结果 | 选择理由 | 依赖 | 完成标准 |
|---|---|---|---|---|---|
| P0 | MomoRay 包装内折页说明卡端到端文件包 | 确认 | 它把真实品牌背景、用户需求、内容结构、文件输出和制作交接连接成一个可理解案例 | 实际尺寸、批准文案、品牌素材、折页结构 | 完成 Print PDF、SVG、检查报告和交接清单 |
| P1 | SVG Checker 规则与验证报告 | 确认 | 它直接证明 Tool 设计、确定性检查、错误信息和机器流程意识，不依赖当前 API | SVG 规则、测试文件、测试脚本 | 至少 8 个测试文件，预期和实际结果一致 |
| P2 | Ask-vs-Act + Creative Brief 前后对照 | 确认 | 它证明 Agent 产品判断和交互设计，并能在 API 阻塞时先以人工/Mock 样例验证 | 场景集、决策规则、Brief Schema | 至少 10 个场景，样例来源和状态标记清晰 |
| P3 | xTool Studio 软件导入记录 | 确认 | 它证明文件确实进入后续软件，而不是只停留在视觉图 | xTool Studio、SVG 样例 | 至少 3 个样例成功导入并核对尺寸 |
| P4 | 端到端交互 Demo | 延后 | 需要前端、服务端和状态逻辑，适合 W3 后完成 | 前述文档、Schema、Mock、Checker | 可录屏演示完整主流程 |
| P5 | 真实模型调用与 Eval | 阻塞 | 是目标岗位的重要技术证据，但当前受 API Billing 限制 | 有效 API 额度 | 完成真实调用、日志、三次复测和 Eval |

## 5. 证据登记要求

### 编号规则

```text
MF-EV-[类别]-[三位序号]
```

示例：

- `MF-EV-BRIEF-001`
- `MF-EV-ASK-001`
- `MF-EV-SVG-001`
- `MF-EV-XTOOL-001`
- `MF-EV-API-001`

### 首批登记信息

| 字段 | 填写规则 |
|---|---|
| 证据编号 | 按编号规则填写 |
| 日期 | 使用实际完成日期 |
| 输入来源 | 用户原始需求 / MomoRay 真实资料 / 人工测试案例 / Mock / 真实模型 |
| 输出来源 | 人工 / Mock / 本地 Tool / 真实模型 / 真实用户 |
| 使用版本 | Brief、Prompt、Schema、Tool 和文件版本号 |
| 验证环境 | 操作系统、软件版本、Python版本、浏览器或设备 |
| 预期结果 | 执行前写明 |
| 实际结果 | 执行后如实记录 |
| 是否通过 | 通过 / 部分通过 / 未通过 / 阻塞 |
| 已知限制 | 明确写出未覆盖的范围 |
| 证据路径 | 本地相对路径或仓库路径 |

## 6. 真实性标签

| 标签 | 含义 |
|---|---|
| 真实过程证据 | 实际完成的研究、设计、决策或复盘材料 |
| 真实业务背景 | 来自 MomoRay 已存在的产品和品牌资料，但不代表 MakerFlow 已用于该业务 |
| 本地 Tool 证据 | 本地确定性工具的实际输入、输出与测试结果 |
| 软件验证证据 | 在 xTool Studio 或其他软件中的真实导入、尺寸和错误记录 |
| Mock 样例 | 本地预设或模拟输出，不代表真实模型能力 |
| 真实模型证据 | 真实 API 调用及可核验记录；当前因 Billing 阻塞，尚不存在 |
| 真实用户证据 | 来自真实用户的脱敏记录；若未执行则不得使用 |
| 实物证据 | 实际打印、裁切或加工结果；未执行前不得使用 |

## 7. 最终结论

### 首批必须完成

1. MakerFlow 一页 Brief 与决策记录；
2. MomoRay 包装内折页说明卡的需求和文件包；
3. Ask-vs-Act 决策案例；
4. Creative Brief 前后对照；
5. SVG Checker 规则、测试文件与报告；
6. xTool Studio 软件导入和尺寸验证；
7. 错误状态与恢复矩阵。

### 可延后

- Web 端到端 Demo；
- 真实设备加工；
- API 接入；
- 真实模型 Prompt A/B 和 Eval；
- 多个自证物和多设备兼容。

### 明确不做

- 企业级生产系统；
- 自动确定设备安全参数；
- 适配全部机器和材料；
- 用 Mock 冒充真实模型；
- 宣称 MakerFlow 已服务 MomoRay 实际业务；
- 宣称说明卡已经量产或提升销售、转化和用户体验；
- 在没有设备验证时宣称已完成真实加工。

### 决策依据

- 包装内折页说明卡与 MomoRay 真实产品背景相关，面试官容易理解；
- 它同时覆盖需求澄清、信息结构、视觉设计、文件交接和 Tool 验证；
- 纸张说明卡的主要交付是印刷 PDF，SVG 只承担矢量图形和刀线，不强行把所有内容塞进激光加工流程；
- SVG Checker 与软件导入验证能够直接对应目标岗位对工具调用、失败处理和机器工艺流的要求；
- API 阻塞不会影响先完成产品定义、规则工具、文件验证和 Mock-first 交互。
