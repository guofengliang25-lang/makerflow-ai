# 07｜知识地图、专有名词、AI产品面试问题

## 1. 核心术语大白话

### JTBD
用户在某种情境下真正要完成的“任务”。

### AS-IS Journey
用户现在不使用MakerFlow时是怎么做的。

### MVP
不是“功能最少”，而是用最小范围验证最关键假设。

### Agent Task Graph
把用户流程翻译成系统任务、责任、分支和恢复路径。

### Node I/O Matrix
定义每个Task节点“吃什么、吐什么、失败去哪”。

### Model
处理模糊/语义/开放问题的概率性组件。

### Tool
对明确输入做明确执行的确定性能力。

### Rule
固定政策与判断准则。

### Human Gate
系统在高影响/责任/不可逆/主观决策处无权自动越过的人工门。

### Skill
Agent可调用的稳定能力单元。

### Skill Registry
系统“会哪些能力”的目录。

### Skill Contract
规定某个Skill怎么调用、I/O、失败、边界和Non-goals。

### Provider Agnostic
DeepSeek/OpenAI可以换，但Skill Contract/Task Graph不应因供应商变化而大改。

### Brief
需求、事实、约束、未确认项的结构化表达。

### Creative Plan
针对未决策事项给出的候选建议及依据。

### Design Spec
最终被接受、可用于渲染Artifact的结构化设计状态。

### Artifact
真正的SVG/PDF等交付作品。

### Project State
当前项目的明确状态/事实。

### Revision
版本；Design Spec revision与Artifact revision必须分开。

### Stale
旧检查结果因为Artifact变化而失效。

### Preflight
制作/交接前检查的总称。

### BLOCK
硬冲突，当前不能继续完整流程。

### WARN
存在风险，可由Human明确接受后继续。

### PASS
通过当前规则，不等于生产安全。

### Ask-vs-Act
Agent自主权策略：ACT / ASK / CONFIRM / BLOCK。

### Risk-based Autonomy
风险越高，Agent自主权越少。

### Deterministic
同样输入/规则下结果可复现。

### Probabilistic
模型对模糊语义问题给概率性输出。

### RAG
从外部知识库检索相关资料，补进模型上下文。

### Context Builder
每次模型调用前，决定该把哪些Project State/Session/RAG信息放进Prompt。

### Decision Log
保存用户接受/拒绝了什么以及为什么。

### Eval
AI产品的考试体系。

### Contract Eval
检查输出结构和硬规则。

### Semantic Eval
检查“质量好不好”。

### Workflow Eval
检查Agent路径和状态转移对不对。

### UX Eval
检查用户是否真的理解和会用。

### Grader
判卷规则/判卷器。

### Baseline
某个版本第一次固定下来的成绩，后续比较用。

### Regression
新版把旧能力搞坏了。

### PRD
定义产品为什么做、给谁做、怎么工作、怎样算对。

### Prompt Inventory
PRD中记录有哪些Prompt，不把所有Prompt全文塞正文。

### Canonical Owner
某一类状态/版本的权威拥有者。

### Authoring Source of Truth
当前创作路径中哪个对象对“设计内容”最权威。

# 2. 用户必须重点理解并应用

## 五星重点
### Eval
要会：
- 定义Success；
- 写Case；
- 定义Expected/Forbidden；
- 选Grader；
- 建Baseline；
- 看Regression。

### AI PRD
要会：
- Problem；
- Why AI；
- Scope；
- Goal；
- Model/Prompt/Eval；
- Authority；
- Acceptance；
- Truth Boundary。

## 四星
### Skill/Contract
要会：
- 判断Skill边界；
- 审I/O；
- 审Non-goals；
- Provider替换不破Contract。

## 三星
### Design Spec / Memory Architecture
要会：
- 判断对象边界；
- 判断什么存/取/忘；
- 不需要自己实现底层基础设施。

# 4. 推荐高质量回答主线

> 我没有把MakerFlow做成“一个LLM什么都干”的Agent。研究后我把任务拆成概率性和确定性两类：自然语言需求理解和Creative Plan由Model处理，SVG渲染与文件解析由Tool完成，Gate和Issue Routing由Rule控制，高影响事实和风险保留Human Gate。随后我通过Skill Contract约束能力I/O，通过Artifact revision和Preflight绑定保证状态一致，并开始用Eval Case把“什么叫做对”变成可重复测试资产。最终PRD不是一篇长文，而是Research、Prototype、Task Graph、Skill、Schema、Authority和Eval的统一入口。
