# 01｜最终目标、关键背景、长期偏好、硬性规则

## A. 最终目标

### 求职最终目标
通过2027秋招/实习准备，转向AI产品岗位，尤其是：
- AI Product
- Agent
- AIGC创作工具
- 创意生产 / Maker / 制作生态
- xTool类AI产品岗位

项目最终不是为了证明“会写代码”，而是让面试官看到：
- 会从JD反推能力；
- 会做用户研究和竞品拆解；
- 会收敛MVP；
- 能分清Model/Tool/Rule/Human；
- 能建立Task Graph和Skill边界；
- 能做Prompt版本管理；
- 能做Eval；
- 能写AI-native PRD；
- 能把Mock Demo做成可运行闭环；
- 对工业设计/制作链路有真实理解。

### MakerFlow最终目标
做一个“规模不一定很大，但逻辑扎实、能跑、能解释、能评测”的旗舰Demo。

核心叙事：
> 从大而全的创作Agent构想，经过企业现有能力拆解、3人访谈和低保真验证，不断删除重复能力，最终聚焦在“结构化约束 → 可编辑Artifact → 确定性Preflight → Issue Routing → Human Gate”。

# B. 关键背景

- 用户有工业设计/AIGC设计背景，正在补齐Agent工作流、Prompt迭代、AI评测等能力。
- 用户希望“理解优先”，不能只让Codex产出大量文档而自己说不明白。
- 用户前期因出游落后进度，因此采用“三天追赶计划”，但明确：赶进度不能牺牲理解质量。
- 当前OpenAI API曾遇到`429 insufficient_quota`阻塞；计划后续接DeepSeek调试。
- DeepSeek尚未真正接入当前MakerFlow Model节点，当前Model能力仍是Mock。
- 当前Demo无需AImake/xTool Studio原生集成，文件级上传/下载即可表达生态位置。

# C. 长期回答偏好

后续回答必须：
- 中文为主；
- 多使用结构化Markdown；
- 先讲大白话，再讲专业概念；
- 理论必须配MakerFlow真实例子；
- 明确区分FACT / DESIGN DECISION / HYPOTHESIS / TARGET / NOT VALIDATED；
- 不确定就写`[待确认]`，不能补写；
- 每个新知识点尽量给Codex操作Prompt；
- 给初学者能直接执行的步骤；
- 同时补“专业面试官会怎么看”；
- 不要只给表面任务表，要深入到输入/输出/状态/失败/验收；
- 允许花时间，优先高质量；
- 用户自己做价值判断，Codex做机械整理/批量结构化；
- 用户必须通过“自己复述”证明理解后再进入下一层。

固定教学/执行格式：
1. 概念是什么；
2. MakerFlow例子；
3. 需要懂到什么程度；
4. 必须亲自判断什么；
5. 具体怎么做；
6. Codex做什么 + Prompt；
7. 验收标准。

# D. 求职真实性硬规则

任何作品集/简历/PRD/面试叙述都必须遵守：

1. 不得虚构上线、真实用户量、商业结果、生产效果。
2. 信息不足写`[待补充]`或`[待确认]`。
3. 用户研究只能推出样本真正支持的结论。
4. P02情境回答不能写成真实生产行为。
5. P01/P03的3D问题只能支持“检查分层/问题后置”架构，不能证明具体SVG规则高频。
6. 不能把官方宣传直接当真实使用效果。
7. 不能把“未在官方文档发现”写成“产品一定没有”。
8. MakerFlow当前Demo没有证明减少时间/返工。
9. 不能声称与AImake/xTool Studio已有原生集成。
10. 文件PASS不等于保证加工成功。
11. xTool Studio真实材料/设备/参数仍需人工/真实软件确认。
12. 当前未接Model API的Skill必须标`mock`或`future_model`，不能写“已使用DeepSeek”。
13. PDF若未真实生成，不能写当前Artifact已支持Verified PDF。
14. `artifact.export`当前核心是本地SVG/摘要，不发送Studio。
15. 任何推荐都不能自动写成用户confirmed事实。

# E. 不能随意修改的产品硬边界

- MakerFlow不是通用图片生成器。
- 不做完整Illustrator/Figma替代品。
- 不做3D建模/3D Checker。
- 不自动决定真实激光功率/速度/次数。
- 不控制设备。
- 不保证安全加工。
- 不把Brief JSON/报告描述成xTool Studio会自动读取。
- 不把材料建议当实际生产材料参数。
- 不把所有历史聊天直接塞给模型。
- 不把RAG当项目事实数据库。
- 不把所有Task强行做成Skill。
- 不把Human Gate做成Skill。
- 不把每个Model建议都要求用户重复确认，Human Gate需有风险/责任理由。
