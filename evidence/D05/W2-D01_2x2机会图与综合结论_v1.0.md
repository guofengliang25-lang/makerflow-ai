# W2-D01｜2×2 机会图与综合结论 v1.0

> 阶段：W2 产品定义  
> 证据性质：基于现有工作流资料形成的研究结论，不代表完整产品实测  
> 事实标记：未亲自操作或未留存截图的能力均标记为 `[待实际验证]`

## 1. 研究问题

MakerFlow 是否存在一个值得验证的产品位置：在用户得到视觉结果之前补齐制作约束，在文件进入制作软件之前暴露可确定检查的问题，并保留可编辑、可追溯的中间决策。

## 2. 2×2 坐标轴

- 横轴：中间过程的可编辑、可解释程度。
  - 左侧：主要接受生成结果，约束和决策依据不可见或难以编辑。
  - 右侧：Brief、建议、文件和检查结论均可编辑，并保留依据与人工确认记录。
- 纵轴：从数字创作进入真实制作流程的覆盖深度。
  - 下侧：停留在数字内容生成或常规文件导出。
  - 上侧：覆盖文件检查、制作软件交接、软件内设置和加工前人工确认。

## 3. 机会图定位

| 对象 | 横轴判断 | 纵轴判断 | 证据边界 |
|---|---|---|---|
| AI 视觉生成工具 | 偏低到中 | 偏低 | 多数以视觉结果为主要产物；具体工具能力需逐项验证 |
| Illustrator / Inkscape | 高 | 中 | 提供专业编辑和导出能力，但约束识别主要由用户承担 |
| AImake | 中到高 `[待实际验证]` | 中到高 `[待实际验证]` | 官方信息显示其面向制作场景并提供主动建议；可编辑深度、导出和失败状态尚未完整实测 |
| xTool Studio | 中 `[待实际验证]` | 高 `[待实际验证]` | 位于文件导入、设置、预览与设备交接阶段；具体导入和设置行为待实际验证 |
| MakerFlow 假设位置 | 高 | 高 | 不是替代专业设计或机器软件，而是连接约束澄清、可编辑记录、文件检查和人工交接 |

## 4. 三个机会判断

### 机会 A：把约束显性化，但不替用户做高风险决定

Creative Brief 确认后，MakerFlow 可以提供形式、尺寸、材料、颜色、版式与可读性、制作路径和输出格式的候选建议。每条建议必须公开依据、收益、取舍、信心和确认要求。

该层用于降低用户整理约束的负担，不是 MakerFlow 的核心差异，也不得决定机器功率、速度、次数或安全参数。

### 机会 B：把检查拆成进入 Studio 前和进入 Studio 后两段

单一的“通过/失败”不足以表达文件问题发生在哪里。MakerFlow 应将 Checker 分为：

- Pre-import Gate：进入 xTool Studio 前解决或确认的问题；
- Studio Setup Checklist：文件进入 Studio 后、加工前必须完成的设置和确认。

这能避免把“文件可导入”“文件已准备加工”和“实际加工安全”混为一谈。

### 机会 C：用可追溯记录连接工具，而不是声称系统自动互通

Creative Brief、Constraint Recommendations、Checker 报告和决策记录是用户项目记录。xTool Studio 的主要输入仅为通过 Pre-import Gate 的 Verified SVG/PDF。当前没有证据表明 Studio 会自动读取 Brief、Checker JSON 或交接包，因此不把自动读取作为产品能力。

## 5. 综合结论

MakerFlow 当前最值得验证的差异不是“更懂材料参数”或“比现有工具更会生成”，而是：

1. 在生成候选设计前识别缺失信息，并使用 Ask-vs-Act 保留必要确认；
2. 形成 Editable Creative Brief 和可追溯决策记录；
3. 将确定性文件问题提前到 Pre-import Gate；
4. 将 Studio 内的设置、Preview/Framing 和加工前确认明确交还给用户；
5. 用 Verified SVG/PDF 作为跨系统交接产物，不虚构 JSON 自动互通。

Constraint Recommendations 是辅助层。SVG Checker 是 MakerFlow 的 Tool 模块，不作为独立第四个主案例，也不替代专业 CAM、Studio 预览、材料测试或设备安全检查。

## 6. 待验证问题

- AImake 的中间结果可编辑范围、建议依据和导出格式 `[待实际验证]`；
- xTool Studio 对 SVG/PDF 的实际导入、尺寸解释和对象识别行为 `[待实际验证]`；
- xTool Studio 中操作类型、Preview/Framing 和加工前确认的实际界面与顺序 `[待实际验证]`；
- 不同 SVG 问题是否会阻止导入、仅产生显示差异或在加工准备阶段暴露 `[待实际验证]`；
- 目标用户是否认为两阶段 Checker 比单一报告更易理解。
