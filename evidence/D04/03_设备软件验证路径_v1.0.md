# MakerFlow 设备与软件验证路径 v1.0

> 文档性质：验证计划，不代表验证已经执行  
> 项目性质：个人作品集 Demo  
> 当前约束：OpenAI API 真实调用因 Billing 阻塞  
> 当前阶段：W1 项目定义完成，进入 W2 用户与产品研究

## 1. 验证目标

- **目标设备范围**：
  - P0：当前个人 Windows 11 电脑；
  - P1：xTool Studio 支持的软件环境；
  - P2：学校、朋友或外部服务商可提供的激光/刀片切割设备 `[待确认]`。
- **目标软件范围**：
  - 浏览器；
  - Illustrator 或 Inkscape；
  - xTool Studio；
  - 本地 SVG Checker；
  - 后续 MakerFlow Web Demo。
- **必须走通的核心路径**：

  `模糊需求 → 关键追问 → Creative Brief → 说明卡设计规格 → Print PDF / SVG → SVG Checker → xTool Studio 导入 → 制作交接`

- **必须留下的证据**：
  - 输入样例；
  - Brief 与人工修改记录；
  - SVG 原文件；
  - Checker 报告；
  - xTool Studio 导入截图；
  - 尺寸对照；
  - 错误与修复记录；
  - Demo 版本号和实际状态。

## 4. 验证路径 A：需求澄清

1. **输入样例**：  
   “帮我做一份放在 MomoRay 枕头包装里的高度调节说明书。”
2. **关键缺失信息**：
   - 展开尺寸与折叠后尺寸；
   - 折页形式；
   - 必须出现的产品文案；
   - 目标用户和阅读场景；
   - 纸张/卡纸类型；
   - 是否需要异形裁切；
   - 品牌素材。
3. **预期 Ask 行为**：
   - 优先追问会改变文件结构、内容真实性和制作方式的信息；
   - 每轮最多提出 3—5 个关键问题；
   - 解释为什么需要这些信息；
   - 不因装饰细节阻塞低保真初稿。
4. **通过标准**：
   - 能识别至少 5 项关键缺失信息；
   - 不直接生成“最终可印刷文件”；
   - 清楚区分必须确认项和可采用默认假设项。
5. **证据形式**：
   - 原始输入；
   - 缺失字段表；
   - 追问内容；
   - Ask-vs-Act 判断依据；
   - 人工评审记录。

## 5. 验证路径 B：Creative Brief

1. **输入样例**：需求澄清后的用户回答、MomoRay 产品事实和品牌素材。
2. **预期 Brief 字段**：
   - 项目目标；
   - 目标用户；
   - 使用场景；
   - 说明卡形式；
   - 展开/成品尺寸；
   - 内容清单；
   - 品牌要求；
   - 材料与制作方式；
   - 输出格式；
   - 已确认信息；
   - 系统假设；
   - 待确认项。
3. **可执行性检查方式**：
   - 逐字段检查必填项；
   - 由用户人工修改；
   - 检查是否能直接指导排版和文件输出。
4. **通过标准**：
   - 必填字段无空缺；
   - 未确认内容不伪装成事实；
   - 用户能够修改并确认；
   - Brief 能指导后续内容结构和文件制作。
5. **证据形式**：
   - 模糊输入；
   - Brief v0.1；
   - 用户修改记录；
   - Brief v1.0；
   - 字段检查表。

## 6. 验证路径 C：SVG Checker

SVG Checker 是 MakerFlow 内部 Tool，不是独立主项目。

| 样例类型 | 输入 | 预期结果 | 实际结果 | 状态 |
|---|---|---|---|---|
| 合法 SVG | 包含 viewBox、明确尺寸、闭合刀线且无文字对象的 SVG | 通过；返回已检查规则和少量提示 | 待执行 | 计划 |
| 缺少尺寸 SVG | 无 width/height 或与 Brief 尺寸不一致 | 阻塞或警告；说明尺寸问题 | 待执行 | 计划 |
| 含文字对象 SVG | 存在 `<text>` 元素 | 警告转路径或确认字体兼容 | 待执行 | 计划 |
| 含嵌入位图 SVG | 存在 `<image>` 元素 | 标记位图位置和风险 | 待执行 | 计划 |
| 未闭合刀线 SVG | 计划作为裁切路径但路径未闭合 | 阻塞；指出路径位置 | 待执行 | 计划 |
| 边界样例 | 极复杂路径、重复 ID 或空元素 | 输出警告，不做超出规则的结论 | 待执行 | 计划 |

### 计划检查的确定性规则

- SVG 是否可解析；
- 是否存在 `viewBox`；
- 宽度、高度和单位；
- 与 Brief 目标尺寸是否一致；
- 是否包含文字对象；
- 是否包含嵌入位图；
- 是否存在空元素或重复 ID；
- 指定刀线是否闭合；
- 是否存在预设的刀线图层；
- 路径复杂度提示。

### 不属于 SVG Checker 责任的内容

- 设计是否美观；
- 产品文案是否真实；
- 最终印刷色彩是否准确；
- 激光功率、速度等设备参数；
- 全部设备兼容性；
- 实际加工安全；
- 工业级或量产级质量保证。

## 7. 验证路径 D：制作软件交接

1. **导出物**：
   - Print-ready PDF；
   - SVG 矢量/刀线文件；
   - `checker_report.json`；
   - 制作交接清单。
2. **目标软件**：xTool Studio。
3. **导入步骤**：
   - 安装并记录版本；
   - 新建空白项目；
   - 导入 SVG；
   - 核对画布和对象尺寸；
   - 检查文字、路径、位图和图层；
   - 保存截图与问题；
   - 如失败，修复文件并再次导入。
4. **需要检查**：
   - 展开尺寸；
   - SVG 单位；
   - 文字是否转路径；
   - 刀线是否显示；
   - 是否存在丢失或错位元素；
   - 导入后尺寸是否与 Brief 一致。
5. **通过标准**：
   - 至少 3 个测试 SVG 可以导入；
   - 导入尺寸与预期一致，或能解释偏差原因；
   - 关键对象可以被识别；
   - 所有失败均有错误记录和修复结果。
6. **当前边界**：
   - 软件导入成功不等于真实加工成功；
   - 未接触设备前不得宣称完成机器验证。

## 8. Mock 与真实模型边界

- 当前可验证：人工流程、Mock Schema、本地确定性 Tool、错误状态；
- 当前不可声称：真实 OpenAI API 集成已完成或真实模型效果已验证；
- Mock 输出必须显示 `source: mock`；
- 真实模型恢复后需要：
  1. 完成一次成功 Responses API 调用；
  2. 保存请求、响应、Response ID、模型 ID 和用量；
  3. 同一条件运行 3 次；
  4. 使用与 Mock 相同的 Schema；
  5. 运行固定测试集；
  6. 将真实结果与 Mock 分开归档。

## 9. 错误状态

| 场景 | 预期提示 | 恢复动作 | 验证方式 |
|---|---|---|---|
| 输入不足 | “还缺少会影响成品的关键信息”并列出问题 | 用户补充或选择显式默认值 | 人工检查 10 个案例 |
| 输入格式不支持 | 说明支持格式和当前文件问题 | 重新上传或转换格式 | 错误文件测试 |
| Mock 数据异常 | 明确提示本地 Mock 数据错误 | 重置样例或加载备用 Mock | 修改本地 JSON 复现 |
| API 因 Billing 不可用 | 不调用并说明真实模型当前不可用 | 使用明确标记的 Mock 路径 | 无额度环境中运行 |
| SVG 无法解析 | 说明文件无法读取 | 重新导出或修复 XML | 损坏 SVG 测试 |
| SVG 不符合规则 | 列出具体规则、位置和严重程度 | 用户修改后重新检查 | 正常/异常样例对照 |
| xTool Studio 导入失败 | 说明文件层验证通过不等于软件兼容 | 记录错误并修改导出选项 | 实际导入复测 |

## 10. 证据采集

每次实际验证记录：

- 测试编号：`MF-TEST-[类别]-[三位序号]`
- 日期与执行人：实际执行时填写；
- 设备和软件版本：实际执行时填写；
- Demo 版本：实际执行时填写；
- 输入来源：人工 / Mock / 本地 Tool / 真实模型 / 真实用户；
- 输出来源：如实记录；
- 操作步骤：逐步记录；
- 预期结果：执行前填写；
- 实际结果：执行后填写；
- 截图、录屏或日志：保存相对路径；
- 结论：通过 / 部分通过 / 未通过 / 阻塞；
- 已知限制：不得省略。

## 11. 总体通过标准

当前阶段完成以下内容即可视为“验证计划通过”，而不是“产品验证通过”：

1. 已明确设备、软件和文件范围；
2. 已定义需求澄清、Brief、SVG Checker 和软件交接四条验证路径；
3. 每条路径均有输入、预期、通过标准和证据形式；
4. Mock、真实模型、软件验证和实物验证边界清楚；
5. 未确认设备不会阻塞 W2 产品研究；
6. 后续实际执行时能够按编号留下证据。

最终项目验证通过需要额外满足：

- 本地 SVG Checker 实际运行；
- xTool Studio 实际导入；
- 至少 3 条端到端流程测试；
- API 恢复后完成真实模型测试；
- 有设备条件时补充实物加工，不作为当前硬性条件。
